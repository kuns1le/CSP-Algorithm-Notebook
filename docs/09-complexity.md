# 复杂度判断与算法选择

先看 n、m、T、数值上限和总数据量。复杂度不是只看最里面的循环，也不是按题面出现的词选模板。

## 常见量级

以下是候选方向，不是“必定通过”的保证。时间限制、语言、机器、常数、缓存和输入规模都会影响实际耗时。

| 最大规模的粗略量级 | 首先排查的方向 |
| --- | --- |
| n 在十几到二十多 | 子集、状态压缩、回溯；仍需核算 2^n·n 和内存 |
| n 在几百 | O(n²) 常见；O(n³) 需结合具体 n 与时限 |
| n 在几千 | O(n²) 需细算；尽量避免更高次复杂度 |
| n 在 10^5～10^6 | 通常考虑 O(n)、O(n log n) |
| 值域很大、候选单调 | 值域二分、数学化简；单次判定成本也要乘进去 |

例如 n=100000 时 n²=10^10，通常过大；n log2 n 约 1.7×10^6，但一次“操作”可能是昂贵的字符串比较或容器分配，因此不能把这个数直接当运行时间。

## 判断流程

| 题目提供的结构 | 可能的方法 | 必须再确认 |
| --- | --- | --- |
| 规模小、状态数少 | 枚举 / 模拟 | 是否漏解、是否重复、最坏次数 |
| 有序数组 | STL 二分、双指针 | 查找条件、指针移动是否安全 |
| 可行性随答案单调变化 | 答案二分 | 单调性证明、搜索边界 |
| 重复问静态区间和 | 前缀和 | 中途是否修改 |
| 批量区间加后统一输出 | 差分 | 是否真的离线 |
| 最少等权步数 | BFS | 状态完整性、每步代价 |
| 非负边权最短路 | Dijkstra | 有无负边、距离是否溢出 |
| 增量合并集合 | 并查集 | 有无删边、有向关系 |
| 局部选择似乎有效 | 贪心候选 | 交换证明或反例；不能只凭直觉 |
| 有重叠子问题和可用状态 | 动态规划候选 | 状态、转移、初值、计算顺序 |

双指针和动态规划列为判断方向，本版未提供独立完整模板，后续做题时补充。

## 时间怎么算

- 顺序执行相加，保留主导项；嵌套循环看真实迭代次数。
- 每次乘 2 的循环通常是 O(log n)。
- 排序+线性扫描通常 O(n log n)。
- DFS 遍历图是 O(V+E)，枚举所有子集则可能是指数级。
- 二分答案时间是 O(判定成本×log 搜索范围)。
- 多组输入要算总和，例如 sum(n_i log n_i)，不能忽略 T。
- 向上找质数若实际检查 K 个候选、最大检查到 P，试除上界为 O(K sqrt(P))，不能笼统写成 O(sqrt(X))。

## 空间怎么算

- n×m 个 long long 的元素存储约为 8nm 字节，不含容器额外开销。
- 10^5×10^5 邻接矩阵不可行；稀疏图通常用邻接表。
- 递归深度、BFS 队列、Dijkstra 堆、数组副本都占空间。
- vector<vector<int>> 有每行容器开销；unordered 容器有桶和节点开销。
- stack overflow 与总内存足够是不同问题，深递归尤其要检查。

做完复杂度估算后，用符合最大约束的数据做本地计时和内存观察；样例通过只说明样例通过。
